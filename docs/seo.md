# SEO

A link shortener produces mostly thin pages that exist only to send visitors elsewhere.
Indexing those would add nothing for searchers and could look like doorway pages, so the
strategy is: **index the homepage only, keep link pages out of search, but keep them rich
for social sharing.**

## What each page gets

| Page | robots | In sitemap | Notes |
| --- | --- | --- | --- |
| `/` dashboard | `index, follow` (switchable: *Site settings → Allow search engines to index the dashboard homepage*) | Yes, if indexable | Unique title and description from Site settings |
| `/links/<slug>/` (direct, locker, timer) | `noindex, follow` | **No** | Full Open Graph and Twitter tags |
| `/admin/` | `noindex, nofollow` | No | Also `Disallow`ed in robots.txt |
| `404` | `noindex, nofollow` | No | |

All tags come from one component (`src/components/Seo.astro`), so a page can't end up with
duplicate titles, descriptions or canonicals. `scripts/verify-dist.mjs` checks this on every CI build.

## Per-link fields

| Field | Fallback |
| --- | --- |
| SEO title | Title |
| Meta description | Short description, then "<Title> — a short link on <site>" |
| Featured image | Default social image (*Site settings*) |
| Canonical URL override | The link's own short URL |

The canonical override must be an absolute `https://` URL. Anything else fails the build.
Use it when you want search engines to credit another page with your link page's content,
for example the destination article.

## Social sharing

Every page outputs `og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`,
`og:image`, `og:image:alt`, `twitter:card` (`summary_large_image` when there is an image),
`twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt` and, if set,
`twitter:site`. Image URLs are absolute.

Social crawlers don't execute JavaScript, so even **Direct Redirect** pages show a proper
preview card. Use 1200×630 PNG or JPG images; social networks don't accept SVG.

Check a preview with the platforms' debuggers (Facebook Sharing Debugger, LinkedIn Post
Inspector) after deploying. They cache results, so use their "scrape again" buttons after changes.

## Sitemap and robots.txt

- `/sitemap.xml` is generated by `src/pages/sitemap.xml.ts` and lists only indexable pages.
- `/robots.txt` allows everything except `/admin/` and points to the sitemap. Link pages are
  **not** blocked in robots.txt on purpose: a crawler must be able to fetch a page to see its
  `noindex` tag.
- lnkrs.github.io is a user/organisation site served from the domain root, so
  `https://lnkrs.github.io/robots.txt` is the real robots file crawlers read. Also submit
  `https://lnkrs.github.io/sitemap.xml` in Google Search Console.

## What we deliberately don't do

- No Article or Product structured data on redirect pages (they aren't articles or products).
- No generated filler text to attract search traffic.
- No indexing of interstitials.
